# NBA SPM/RAPM Stack — Critique (Mofe, 2026-06-11)

Scope: `src/` (SPM prior pipeline), `rapm/src/rapm_with_prior.py` (old generation),
`rapm/src/standard_rapm.py` + `evaluate_rapm_models.py` (new generation, May 2026).
Companion to the soccer critique at
`soccer rapm/docs/critique_2026-06-10.md`.

## Verdict

Two generations of code live here, and the quality gap is large. The new generation
(`standard_rapm.py` + `evaluate_rapm_models.py`) is genuinely good — game-grouped CV
plus chronological retrodiction, spec ablations, calibration bins, garbage-time
filtering, a standardized rubberband column, prior modes as first-class config,
standard errors, log-scale λ search. It is better validation infrastructure than the
soccer repo had before this week. The old generation (`train_spm.py`,
`generate_priors.py`, `apply_prior.py`, `rapm_with_prior.py`) is where the problems
are — and unfortunately it is the part that manufactures the prior feeding the good
machine. Fix the bridge, not the engine.

## Critical issues, ranked

### 1. The prior is circular (biggest issue, invalidates the posterior product)

`train_spm.py` trains GBMs on 5-year-window RAPM targets, then predicts **on the
same training rows** (`TRAIN_PREDICTIONS` is literally the training set with
predictions appended). `apply_prior.py` then blends those in-sample predictions back
into the same windows' observed RAPM. GroupKFold was used for *hyperparameter
selection only*; the final model is refit on all rows, so the GBM has memorized a
chunk of each window's RAPM noise. Consequences:

- `Posterior_Rapm` double-counts noise rather than canceling it.
- The "undervalued / overvalued by raw RAPM" lists are substantially GBM residual
  artifacts, not insight.

**Fix:** the prior for window/season T must never have seen T. Walk-forward: train
the SPM only on windows ending ≤ T−1 to generate priors for T (this is the
DARKO/EPM discipline). Cheaper stopgap: use cross-fitted (out-of-fold) predictions
instead of in-sample ones. Then re-tune the blend.

### 2. Defensive sign-convention roulette

The def sign flips three times across files: the training target is positive-good
(per dataset convention) → `generate_priors.py` writes `SPM_D = -pred/100` → 
`build_prior_dict` negates again (`-row["SPM_D"]`) → net **+pred/100** enters the
ridge, where a good defender's coefficient must be *negative* (he reduces points per
possession). Each hop has an apologetic comment ("mirror what was originally
expected"), which is how silent sign errors survive. Maybe it nets out correctly —
but nothing in the repo proves it.

**Fix:** one canonical convention documented once, plus an anchor test that runs
with every prior build: e.g., assert the def prior for a known elite defender
(prime Gobert) enters the regression with points-reducing sign, and that
`corr(prior_def, raw_RAPM_def) > 0` on high-minute players.

### 3. Train/inference feature mismatch in `generate_priors.py`

Trained on 5-year-window-averaged features (POE = window mean), inference runs on
single seasons (POE = that year) through the same scaler — single-season stats are
noisier and wider than window averages, so inference inputs sit partly outside the
training distribution. Worse: missing features are filled with raw 0 *before*
scaling at inference (0 raw → −mean/σ after scaling = an extreme value, not a
neutral one), while training *dropped* incomplete rows. Pre-tracking-era players and
anyone with a feed gap get garbage priors, silently.

**Fix:** identical feature constructors for train and inference (one shared module —
the lists are currently copy-pasted and already drifting); impute with training
means (= 0 *after* scaling) or add explicit missingness indicators; window the
inference features the same way as training.

### 4. `PRIOR_WEIGHT = 1000` minutes — the blend's only parameter, never validated

It's hardcoded with a vibes comment. And a constant is the wrong shape anyway: RAPM
precision varies across players beyond minutes (collinearity with teammates). The
new gen already computes ridge standard errors (`standard_errors()` in
`standard_rapm.py`) — use them for inverse-variance blending, and tune the overall
prior strength on the retrodiction harness you already built
(`evaluate_rapm_models.py` can score it out of the box).

### 5. Old `rapm_with_prior.py` — retire it onto the new core

- `RidgeCV(alphas=[4000], cv=4)` — cross-validation over a single alpha is
  decorative; λ is hardcoded with extra steps.
- Playoff exclusion by fixed date window (`season-04-12` to `06-30`) breaks for the
  2020 COVID season (played Jul–Oct, playoffs Aug–Oct in the bubble) and the 2012
  lockout. The new gen has `playoff_window(season)` — confirm it special-cases
  2012/2020/2021, then delete the old filter everywhere.
- `run_ridge_model_with_prior` fits an entire second ridge just to also return raw
  coefficients — 2× compute for a column.
- The `all_players` collection loop is pasted twice back-to-back.
- DB password hardcoded in source. Move to env var and rotate it.
- Credit where due: the offset-prior algebra (fit on `y − Xβ₀`, add β₀ back) is
  textbook-correct.

### 6. `train_spm.py` — structural cleanups

- `models_config` and `optimize_target` are each defined **twice**; the second
  silently shadows the first (RandomForest only exists in the live copy). Dead code
  like this is exactly what a future session edits by mistake. Delete the first.
- `StandardScaler` on tree models is a no-op that adds an inference artifact and a
  fake leak-smell for nothing. Drop it (or keep it only if you add linear models —
  which you should, see below).
- The "evaluation" section prints top-5 players per window **on training
  predictions** — eyeball validation on train. The real SPM test is: does the prior
  improve *next-season* retrodiction in the evaluator? Wire that in as the gate.
- GroupKFold by player is the right instinct (the same player's overlapping windows
  would leak badly), but overlapping windows still share eras and teammates across
  groups, so CV RMSE is mildly optimistic. A time-forward outer check fixes the
  honest number.
- Trees clip at the tails — exactly where your best players live. A generational
  outlier season gets predicted at the max leaf value. Standard remedy in the
  EPM/DARKO lineage: blend a regularized linear model with the GBM (stacking), or
  use monotone constraints on the obvious features.

### 7. Target construction bakes in double shrinkage

Low-minute windows have RAPM targets already shrunk toward 0, so the SPM learns the
*shrinkage*, not the talent; then `apply_prior` makes the prior dominant for exactly
those low-minute players → fringe players are shrunk twice. Mitigate: train on
high-minute windows only, or weight by RAPM posterior precision (you have SEs now),
not raw minutes.

## What's good — keep and build on

- The whole `evaluate_rapm_models.py` pattern: ablation specs (player-only → +home →
  +rubberband → +season → garbage-time toggle), two split regimes (game-grouped CV
  and chronological retrodiction), calibration-by-decile tables, run-metadata JSON.
  This *is* the scorecard discipline; it should be the template for the soccer
  harness (soccer task #2).
- Garbage-time filtering with a period-progress threshold; standardized score-margin
  (rubberband) meta column; prior modes zero/offset/dummy as config, not forks.
- Log-scale coordinate descent with a halving step for λ — strictly better than the
  soccer repo's fixed-grid search; port it there.
- Three-layer architecture (box/tracking SPM → prior → possession RAPM) is the
  correct NBA stack. The layers are right; the plumbing between them is what leaks.

## Priority order

1. Walk-forward (or at minimum out-of-fold) SPM priors — kills the circularity.
2. Sign-convention audit + anchor unit tests on the def pathway.
3. Tune the blend (per-player inverse-variance via SEs; strength via retrodiction).
4. Fix generate_priors feature/scaler/imputation mismatch; single shared feature module.
5. Migrate old scripts onto the `standard_rapm` core; delete dead code; env-var the DB password.
6. Data-quality report (see below).

## Data quality bar (applies to both repos)

Every ingested source ships with a generated report: (a) **dedup audit** —
possession/stint row uniqueness on natural keys; (b) **coverage** — ≥95% of
player-minutes (or possessions) matched to canonical IDs, per season; (c)
**reconciliation** — team totals vs official (5×48×games minutes in NBA;
11×(90+stoppage) in soccer; points/goals vs league tables). The NBA dump was a gift,
but the 2020 date-filter bug shows why gifts get audited too.

## Cross-sport lessons worth stealing

- **Hockey** (closest cousin to soccer): xG-RAPM over goals-RAPM is settled there;
  and the mature products are *component* models — separate even-strength / power
  play / penalty kill values summed into WAR. Translation: state-split RAPM —
  halfcourt vs transition in NBA, open-play vs set-piece in soccer — instead of one
  monolithic number.
- **NFL**: where lineups don't vary (offensive line), plus-minus is dead and the
  field moved credit assignment into play-level EPA models. Lesson: when
  identification is weak, push attribution into the event-value model and let
  plus-minus be the glue/validator, not the headline.
- **Cricket**: bowler-vs-batter is an isolated 1v1, which is why attribution works
  there. You can *manufacture* isolation statistically: NBA publishes who-guarded-
  whom matchup data — matchup-conditioned defensive RAPM is buildable today. (Also:
  Duckworth-Lewis is the original state-value/EPV function — overs+wickets → expected
  runs.)
- **Baseball**: catcher framing models are crossed random effects separating
  catcher/pitcher/umpire/batter on the same event — a literal solved instance of
  the teammate-collinearity problem. And DRC+ publishes uncertainty with every
  number; nobody in public NBA/soccer does this well. Cheap differentiation.
- **Meta-pattern**: every sport that matured converged on (1) an event-level value
  model for credit, (2) hierarchical shrinkage with context priors, (3) plus-minus
  as validation. RAPM-first is an NBA-historical accident, not a law.

## Creative directions (the non-boring list)

Prior-informed RAPM is plumbing — necessary, but metric-chasing as research. Things
that would actually be new and fun, both sports:

1. **Portability score**: trades/transfers as natural experiments, productized —
   "how much of this player's value travels with him?" Directly answers the
   is-he-good-or-is-it-the-system argument fans actually have.
2. **Matchup-RAPM** (NBA, data exists publicly): defensive impact conditioned on
   who you actually guarded. The cricket-duel trick applied to basketball.
3. **Counterfactual lineup/squad engine**: "swap X onto team Y" with honest
   uncertainty bands, powered by the posterior *covariance* everyone throws away —
   the covariance encodes exactly which player separations the data can't make.
4. **State-split component WAR**: halfcourt/transition (NBA), open-play/set-piece
   (soccer), summed like hockey GAR. More interpretable and more checkable than one
   number.
5. **Era-translation engine**: league/season FE chains let you move players across
   eras and leagues rigorously — evergreen public-facing content with real method
   underneath.
6. **Uncertainty tiers as a product feature**: every published rating gets a
   confidence grade from the bootstrap/SEs. Nobody does it; it's nearly free.
7. **Referee/official effects block** (soccer): cards, penalties, stoppage time as
   meta-columns — legitimately underexplored and extremely shareable.
