# zTS Project — Agent Charter

## Goal

Compute **zTS** (playtype-adjusted relative True Shooting) for NBA players from 2014 onward.

This project is a clean, focused implementation of a single metric. Do not fold in SPM, RAPM, or
other models. Keep every file small and purposeful.

---

## What Is zTS?

zTS is a playtype-adjusted version of rTS (relative True Shooting percentage).

```
rTS       = player_TS% − league_TS%
ExpectedTS = Σ (playtype_share × league_TS%_for_that_playtype)
Difficulty = league_TS% − ExpectedTS          # positive = harder role
zTS        = rTS + Difficulty
           = player_TS% − ExpectedTS          # simplified form
```

**Intuition:** two players with identical raw TS% who score on completely different playtype mixes
have not solved the same problem. A creator running ISO at 52% expected TS is outperforming
differently than a roll man whose expected TS is 60%. zTS makes that difference visible.

### Playtype Buckets

| Bucket      | Synergy Key  | Role                          |
|-------------|--------------|-------------------------------|
| Creation    | `iso`        | Isolation scorer              |
| Creation    | `pr_ball`    | Pick-and-roll ball handler    |
| Creation    | `post`       | Post-up scorer                |
| Spacing     | `off_screen` | Off-screen cutter/shooter     |
| Spacing     | `hand_off`   | Handoff receiver              |
| Spacing     | `spot`       | Spot-up shooter               |
| Finishing   | `pr_roll`    | Pick-and-roll roll man        |
| Finishing   | `oreb`       | Putback/offensive rebound     |
| Finishing   | `misc`       | Miscellaneous finisher        |
| Finishing   | `cut`        | Cutter                        |
| Transition  | `tran`       | Transition scorer             |

### TS% Formula

```
TS% = PTS / (2 × (FGA + 0.44 × FTA))
```

For playtype-level TS%, FTA is estimated from Synergy's `FTFreq%`:

```
FTA_est = FTFreq% × Poss × 2
```

League TS% per playtype is computed bottom-up from all qualifying players each season
(minimum 20 Synergy possessions to be included in the league average).

## Data Sources

| Data              | Location                                                                 | Notes                                  |
|-------------------|--------------------------------------------------------------------------|----------------------------------------|
| Player box scores | `../playersheets/year_totals/{YEAR}.csv`                                 | Has PTS, FGA, FTA, PLAYER_ID, year     |
| Synergy playtypes | `https://raw.githubusercontent.com/gabriel1200/site_Data/master/playtype.csv` | Player-level, 2014–present        |

**Column reference — box scores:**
`PLAYER_ID`, `PLAYER_NAME`, `PTS`, `FGA`, `FTA`, `Minutes`, `year`

**Column reference — Synergy playtype CSV:**
`PLAYER_ID`, `Player`, `year`, `playtype`, `Poss`, `Points`, `FGA`, `FGM`, `FTFreq%`

Coverage note: Synergy data begins in 2014. zTS is therefore only computable from 2014 onward.
Players below 20 Synergy possessions are excluded from league playtype averages.
Players below 250 minutes in a season are excluded from the final output.

## Feature Engineering — `src/features.py`

All player-season features beyond zTS live here. `compute_all_features(box_df)` returns the full table.

### Feature Groups

| Feature | Source | Notes |
|---------|--------|-------|
| `Creation`, `Load`, `ThreePtP` | Box scores | BPM-style offensive generation |
| `cTOV_pct` | Box scores | TOV_per100 / Load — controlled turnover rate |
| `PasserRating` | Box scores | Logistic score (0–11.3); height defaults to positional estimate |
| `TightThree_per100` | Box scores | Contested 3-pt creation under pressure |
| `RimAssists_per100` | Box scores | Passes that lead to rim FGM |
| `Assisted2s_pct`, `Assisted3s_pct` | Box scores | Share of FGM that came off an assist |
| `OffFoulsDrawn_per100` | Box scores | Offensive fouls drawn per 100 off poss |
| `RimPointsSaved` | `defense/rimdfg.csv` | Rim defense impact vs league avg Diff% |
| `C6_DFGA_per100`, `C6_Diff_pct` | `player_tracking/close_6.csv` | Perimeter/closeout defense load + effectiveness |
| `Deflections_per100`, `ChargesDrawn_per100` | `hustle/hustle.csv` | Hustle defense (2018+ only) |
| `Contested2PT/3PT_per100` | `hustle/hustle.csv` | Contested shots per 100 def poss |
| `fTOV_per100` | Box + Hustle | Forced stops: (STL + Deflections + ChargesDrawn) / DefPoss × 100 |
| `OREB/DREB_Contest/Uncontest/Defer_per100` | Box scores | Rebounding quality splits |
| `PotentialAst_per100`, `SecondaryAst_per100` | `player_tracking/passing.csv` | Playmaking tracking |

Drive efficiency (`Drives_per100`, `DrivePts_per100`, etc.) is available via
`compute_drive_efficiency()` but **excluded from `compute_all_features`** — use direct call if needed.

### On RAPM-Adjacent Stats as Box Features

**Short answer: do not include on/off ratings or RAPM-derived estimates in a box-score model used as a RAPM prior.** That is circular — the box model would partially predict the same signal it's trying to explain.

For general player profiling, clustering, or non-RAPM downstream tasks, RAPM-adjacent stats are valid features. The features here are all direct-measurement (box, tracking, hustle) rather than model-derived, which keeps them safe for any use case.

## Known Limitations

- Synergy playtype data starts in 2014; no zTS before that season.
- FTA per playtype is estimated (FTFreq% × Poss × 2), not exact.
- Players with very low Synergy possession counts have noisy playtype shares.
- The GitHub playtype source (`gabriel1200/site_Data`) may not always be current-season complete.
- Passer Rating uses positional height estimates (no height column in source data). Rankings are robust but absolute values are approximate.
- Hustle stats (deflections, charges) are only available from 2018 onward.
